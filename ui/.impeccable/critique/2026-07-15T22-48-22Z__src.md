## Anti-Patterns Verdict

**Deterministic scan**: 11 findings across 7 files, 0 in `src/app` (all in `src/components`).
- `gray-on-color` (4): `EntityForm.tsx:317,473`, `LocationPicker.tsx:59`, `AuthorizedViewersSection.tsx:82` — all `text-gray-400 hover:text-red-500 hover:bg-red-50` remove-icon buttons. **False positive**, confirmed twice now across two independent critique passes: gray is the resting-state color and never co-occurs with the hover-only red background: `:hover` swaps both properties together.
- `design-system-font-size` (7): `0.8rem` used in `CertificateFields.tsx:51,66`, `ProductForm.tsx:1051,1628`, `button.tsx:31`, `form.tsx:96,114`. Split verdict: `button.tsx`/`form.tsx` are ShadCN primitive scaffolding (likely out of DESIGN.md's scope by convention, not a deviation); `CertificateFields.tsx`/`ProductForm.tsx` reuse the identical `0.8rem` value consistently for `text-destructive` form-error messages, which reads as an intentional, repeated convention rather than four independent slips — but it's still technically undocumented in DESIGN.md's type ramp. Worth a single named token (`text-error-hint` or similar) rather than 4 separate raw arbitrary values, or an explicit addition to DESIGN.md's ramp if `0.8rem` is meant to be a first-class size.

## Overall Impression

The document-issuance core (fiscal forms, SEFAZ error handling, list/detail views) is genuinely well-crafted and specific — this doesn't read as AI slop where it matters most. The gaps are in the seams: dead code left behind by an earlier generation pass, one page (Certificates) that quietly opted out of two shared safety patterns (`Modal`, `useEntityDelete`), and an inverted risk-weighting where reversing an action (cancel) is more heavily guarded than performing it (emit). Biggest opportunity: put a confirm step in front of "Emitir NF-e" — right now the app's single highest-stakes, legally-binding action is one undifferentiated `size="sm"` click.

## What's Working

1. **SEFAZ rejection surfacing** (`DfeDetail.tsx:196-213`, `status-badge.tsx:39-63`) — full untruncated motive/protocol, reachable via tap-to-open modal from every list row, not a hover tooltip that would break on mobile. The single most trust-critical surface in a fiscal SaaS, done right.
2. **`useEntityDelete`** (`lib/hooks/useEntityDelete.ts`) — shared optimistic-delete-with-undo-toast, applied uniformly across products/persons/vehicles/members. Makes Certificates' departure from it stand out as a real gap, not a style choice.
3. **`useKeyboardShortcuts.ts`** — correctly suppresses shortcuts while an input/textarea/select is focused, explicit opt-in for global keys (Escape/`?`). Easy to get wrong; done right.

## Priority Issues

**[P0] No confirmation before the app's single highest-stakes action**
- **Why it matters**: "Emitir NF-e" (`NfeEmitForm.tsx:1726-1728`) submits directly to SEFAZ on one click, creating a legally-binding tax document — same visual weight as "Próximo →". Meanwhile Cancelar gets a full modal, red styling, and a mandatory 15-char justification. Risk-weighting is backwards: undo is hard-gated, do is not gated at all.
- **Fix**: add a confirm step before `handleSubmit` — restate destinatário, total, product count; copy like "Confirmar emissão para SEFAZ? Esta ação não pode ser desfeita diretamente." Doesn't need the full justification-field treatment cancel has.
- **Suggested command**: `/impeccable harden`

**[P1] Certificates page skips the app's own modal and delete-safety patterns**
- **Why it matters**: `UploadModal` (`app/certificates/page.tsx:36-116`) hand-rolls a dialog instead of `@/components/ui/modal`, silently losing focus-trap, Escape-to-close, body-scroll-lock. `CertRow`'s delete fires the mutation immediately, no confirm, no undo — while every comparable list uses `useEntityDelete`. A certificate (the signing artifact for every fiscal document an org issues) is the one entity you can delete with zero safety net.
- **Fix**: replace `UploadModal` with `<Modal>`; route delete through `useEntityDelete` or a real confirm modal given the stakes.
- **Suggested command**: `/impeccable harden`

**[P2] Dead legacy `Header.tsx` with a non-functional logout button**
- **Why it matters**: imported nowhere (confirmed via grep), ships `bg-primary-600` (old token, not `brand-600`), and a `<button>Sair</button>` with no `onClick` at all. Landmine for the next person who greps "Header" and wires it back in.
- **Fix**: delete it (`Topbar.tsx` is the live header).
- **Suggested command**: `/impeccable distill`

**[P3] Undifferentiated empty states app-wide + one duplicated one-off**
- **Why it matters**: `EmptyState` (`components/ui/empty-state.tsx:12-19`) has no icon prop, so every list (NF-e/NFC-e/CT-e/MDF-e/products/vehicles/persons/members/audit) shows the identical generic four-square glyph. Certificates bypasses it entirely with a hand-copied shield SVG duplicated from `Sidebar.tsx`'s `ShieldIcon` instead of an import.
- **Fix**: add an optional `icon` prop to `EmptyState`, feed it the already-defined per-doc-type icons; make Certificates consume the shared component.
- **Suggested command**: `/impeccable colorize`

**[P4/minor-but-flagged] Repeated arbitrary `0.8rem` font-size instead of a named token**
- **Why it matters**: detector-confirmed 4x repetition in app code (`CertificateFields.tsx`, `ProductForm.tsx`) of an undocumented size for destructive form-error hints — consistent enough to be a real convention, just never named per project's own "no magic strings/values" rule.
- **Fix**: add `0.8rem` to DESIGN.md's type ramp as a named size, or extract a `text-error-hint` utility class.
- **Suggested command**: `/impeccable typeset`
