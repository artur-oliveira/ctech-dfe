## Anti-Patterns Verdict

**Not AI slop.** Purpose-built fiscal-tool UX. All absolute bans clean: zero side-stripe borders, zero `bg-clip-text` gradient text, zero decorative glassmorphism, no hero-metric template, no filler card grids. `01/02/03` appears only on the landing "Como funciona" explainer (a legitimate real sequence). The contextual `data-dfe-theme` accent system (one library → four doc-type identities, zero per-type markup) and the doc-neutral status badges are genuine, correctly-executed signatures.

Two tells keep it from feeling hand-designed rather than generated: (a) the uppercase+tracked label is over-applied — every SectionCard/CollapsibleSection/InfoCard header uses it, so it reads as a uniform eyebrow rather than a hierarchy cue; (b) the landing (`app/page.tsx`) is a category-reflex long-scroll SaaS template. The app surfaces (the real product register) are calm and distinctive; the marketing page is the weak link.

**Deterministic scan** (`detect.mjs`, exit 2, 23 findings): 4× `gray-on-color` warnings + 19× `design-system-font-size` advisories.
- **4× `gray-on-color` = all FALSE POSITIVES** (verified in source). Files: `EntityForm.tsx:316,471`, `LocationPicker.tsx:59`, `AuthorizedViewersSection.tsx:82`.

Detector clean ≠ contrast clean.

## Overall Impression

This is a strong, calm, genuinely-designed fiscal workspace that mostly lives up to its "Quiet Operator" north star. The system-status feedback, error prevention, and the doc-type theming are category-competitive. The single biggest opportunity is finishing the accessibility promise the product advertises (WCAG 2.1 AA / eMAG): destructive actions currently render at ~3.76:1 — below AA — which both under-signals risk at the highest-stakes fiscal moments *and* breaks the product's own stated baseline. Fix that and tighten mobile touch targets and the score moves into the high 30s.

## What's Working

1. **Contextual `data-dfe-theme` accent system** (`globals.css` + `lib/theme/dfe-theme.ts`) — recolors the entire surface via one CSS attribute, accents scoped to structural surfaces, MDF-e even remaps `--brand-600` to amber-600 for AA. The product's true personality, executed right.
2. **Doc-neutral status badges** (`status-badge.tsx`) — fixed green/red/amber/gray, intentionally NOT recolored by theme, so "Autorizada" is instantly recognizable across all four doc types. Documented, disciplined, rare.
3. **Glossary via the HTML Popover API** (`glossary-term.tsx`) — top-layer render escapes form `overflow` clipping, works on touch (unlike `title`), anchor-positioned with fallback. The correct pattern for fiscal jargon.

## Priority Issues

### [P1] Destructive-action text fails WCAG AA — 21× `text-red-500` + 1× `text-red-400`
**Why it matters:** `text-red-500` (#ef4444 ≈ 3.76:1) and `text-red-400` (#f87171 ≈ 2.77:1) are below the 4.5:1 the product promises (eMAG/AA). Resting destructive text ("Cancelar", "Remover", "Trocar", "remover", "Limpar", the duplicata "×") is the one place contrast matters most — weak contrast literally under-signals risk at cancel-an-authorized-doc / delete-a-product moments. The prior round's red-500→red-600 pass missed the form/page buttons. Detector cannot catch this (it only checks gray-on-color pairs), so it stayed invisible.
**Confirmed resting-state hits:** `app/nfe/page.tsx:470`, `app/nfce/page.tsx:178`, `app/mdfe/page.tsx:107`, `app/persons/page.tsx:137`, `app/vehicles/page.tsx:130`, `app/certificates/page.tsx:146`, `app/members/page.tsx:154,208`, `components/nfe/NfeEmitForm.tsx:205,584,696,1363,1515`, `components/nfce/NfceEmitForm.tsx:158,325,579`, `components/mdfe/MdfeEmitForm.tsx:576,718,742`, `components/products/ProductForm.tsx:1063,1657`; `text-red-400` at `components/nfe/NfeEmitForm.tsx:1550`. (The 4 `text-gray-400 hover:text-red-500` ghost buttons are NOT in scope — that red-500 is a hover state.)
**Fix:** Standardize resting destructive text to `text-red-600` (≈4.83:1); replace the lone `red-400` with `red-600`. Add a `text-danger` token so this can't drift again.
**Suggested command:** `/impeccable colorize`

### [P2] Mobile touch targets under 44px on primary/destructive controls
**Why it matters:** CLAUDE.md hard-mandates `min-h-11` (44px) at 375px. The `.ts-mobile` card-table pass was done well, but key controls remain sub-44px, causing miss-taps during the most error-prone task (issuing).
**Hits:** sidebar overlay nav items `py-2` ~36px (`Sidebar.tsx:220`); Topbar hamburger `size="icon-sm"` 28px + user-avatar no `min-h` (`Topbar.tsx:110-118`); emit-form qty steppers `h-8 w-7` 32×28px (`NfeEmitForm.tsx:620,627`); `+ Adicionar` / destructive row actions at `size="xs"`/`sm` 24-28px (`products/page.tsx:116,124`).
**Fix:** `min-h-11 sm:min-h-0 sm:h-8` on nav items, hamburger, and primary/destructive mobile buttons.
**Suggested command:** `/impeccable layout`

### [P2] Token drift in elevation, neutrals, and font sizes
**Why it matters:** DESIGN.md defines a single shadow scale and single muted token; stray values break the "one quiet system" promise and make theming fragile.
**Hits:** `shadow-sm` (landing cards `page.tsx:237`), `shadow-lg` (glossary/suggestion popovers `glossary-term.tsx:46`) instead of `shadow-card`/`shadow-modal`; `gray-400` (anchored #64748b) and `gray-500` (#6b7280) used interchangeably for secondary text (both pass AA — consistency nit, not a11y); 11 off-scale font sizes (detector) concentrated in `authorization-card.tsx`, px-literals in `Sidebar.tsx`, and 10px MDF-e stepper labels.
**Fix:** Route every shadow through the `shadow-card`/`shadow-card-hover`/`shadow-modal`/`shadow-topbar` scale; pick one secondary-neutral token; move px/off-ramp font sizes onto the rem scale (verify the 10px MDF-e labels for mobile legibility).
**Suggested command:** `/impeccable polish`

### [P3] Landing is a generic long-scroll SaaS template
**Why it matters:** `app/page.tsx` (hero → docs → how → benefits → 5-tier plans → roadmap → footer) is category-reflex and outside the "Quiet Operator" register; it buries the actual product behind marketing convention, and pre-auth pricing pre-empts the SSO-arriving escritório buyer.
**Fix:** Distill to hero + supported doc types + one trust block; move plans/roadmap below the fold or to `/precos`.
**Suggested command:** `/impeccable distill`

### [P3] Delete-undo is silent
**Why it matters:** `useEntityDelete` hides the row inside an undo window but shows no "Desfazer" affordance — at a "did I just delete that?" moment, silence creates avoidable anxiety.
**Fix:** Emit a transient `sonner` toast — "Produto excluído · Desfazer" — during the undo window.
**Suggested command:** `/impeccable delight`

Not pure-design, but the difference between "calm" and "still tedious" for the heaviest daily user.
