# NFCom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Emitir, consultar e cancelar NFCom (modelo 62) pelo DF-e, com contingência offline, DANFE-COM, webhooks e UI.

**Architecture:** Mesmo caminho do MDF-e: `go-dfe` (tipos genéricos por `docType`, XSD vendorizado, tabela de endpoints, validação pré-SEFAZ), worker SNS/SQS por Lambda (`nfcom-emission`, `nfcom-event`), API com pacote `services/nfcoms` e tabelas DynamoDB, UI Next.js. SOAP síncrono, sem lote, sempre pela `go-dfe-egress`.

**Tech Stack:** Go (go-dfe, worker, api, Fiber v3), AWS CDK TypeScript, DynamoDB, Next.js 16.

**Spec:** `docs/specs/2026-11-15-nfcom-design.md` (contexto: `docs/specs/2026-11-15-novos-documentos-svrs.md`). Plano do BP-e depois deste.

## Global Constraints

- Schema vigente: pacote `PL_NFCOM_1.00_NT2026.005 RTC SN 1.00` (19 XSD). O XSD vence o MOC Anexo I (v1.00a, 01/2023, desatualizado para IBS/CBS e Simples).
- Chave de 44 posições: cUF(2) AAMM(4) CNPJ(14) mod(2) série(3) nNF(9) tpEmis(1) nSiteAutoriz(1) cNFCom(7) DV(1), módulo 11 pesos 2 a 9; CNPJ alfanumérico aceito.
- Serviços v1.00: `NFComRecepcao`, `NFComConsulta`, `NFComStatusServico`, `NFComRecepcaoEvento`. Síncrono, sem lote. Sem inutilização, sem distribuição.
- Assinatura XMLDSig enveloped sobre `infNFCom`, RSA-SHA1, C14N. Certificado A1 com CNPJ. Fiscal sempre via `go-dfe-egress`.
- Eventos do emitente na v1: cancelamento 110111 (120 h, `xJust` 1 a 255, `nSeqEvento` 1), vinculação de pagamento 110300 e cancelamento 110301.
- Fora da v1: substituição, ajuste, cofaturamento (`finNFCom` 3 e 4, `tpFat` 2), eventos de fisco e tributação SN emitidos pelo emitente.
- Contingência só offline (`tpEmis=2`): `dhCont` e `xJust` obrigatórios, mesma chave, transmitir até o fim do 1º dia útil seguinte, QR Code com `sign`.
- Billing: entra no plano sob demanda apenas, sem limite próprio.
- Sem travessão em texto visível; sem PFX, segredo ou CNPJ real no repositório; `npm run lint` com zero avisos antes de commit de UI; todo recurso de UI no `/guide` com captura e registrado em `ui/src/lib/navigation/nav.tsx`; docs atualizados na mesma mudança.
- Commits sem trailer de atribuição. Sem `docs/superpowers/`.

## Review Focus

- NFCom com `nSiteAutoriz` diferente de 0 (site alternativo) é aceita e a chave bate o DV.
- Cancelamento fora das 120 h devolve o problema do autorizador (cStat 220), sem retry infinito.
- Emissão repetida (mesmo `Idempotency-Key`) não gera dois `nNF`.
- Contingência offline transmitida depois: mesma chave, protocolo gravado, webhook `document.authorized` uma vez.
- Retorno com cStat 100 sem protocolo ou XML malformado do autorizador não grava documento como autorizado.
- Emitente de UF sem autorizador mapeado devolve erro claro, não chamada a URL vazia.
