# NFS-e — Fase F4: Frontend (Next.js) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar no `ui/` o catálogo de serviços, a configuração NFS-e, o wizard de emissão, a
listagem/detalhe com timeline de eventos e a tela de distribuição ADN, consumindo exclusivamente as
rotas que a F3 publicou.

**Arquitetura:** Espelho estrutural do que já existe. `/services` é um clone de `/products`
(`usePagination` + `useEntityDelete` + `TableShell` + form em `EntityForm`); a aba NFS-e entra no
`/fiscal-config` já tabulado; `/nfse` clona a listagem de `/nfe` **sem** as abas
recebidas/transportadas; `/nfse/emit` é um wizard de cinco passos no mesmo formato do
`NfeEmitForm`. Nenhuma regra fiscal nova é decidida no front: toda validação de negócio já existe
na API e o front só antecipa a mensagem.

**Tech Stack:** Next.js 16 (App Router), React 19, TypeScript, TanStack Query v5, react-hook-form +
Zod, Tailwind 4, ShadCN, `sonner` para toast, `axios` via `apiClient`. **Zero dependências novas.**

**Spec:** `docs/specs/2026-08-04-nfse-design.md` §5 (contrato das rotas), §7 (telas).
**Depende de:** F1 (tabelas de referência geradas em `ui/src/lib/data/`), F3 (todas as rotas).

## Decisões que esta fase carrega das anteriores e não pode reabrir

1. **A rota do wizard é `/nfse/emit`, não `/nfse/new`.** A spec §7 escreveu `/nfse/new`, mas as
   quatro telas equivalentes já existentes são `/nfe/emit`, `/nfce/emit`, `/mdfe/emit`. Divergir
   num único documento fiscal seria inconsistência gratuita. A Task 7 corrige a spec.
2. **`GET /nfses/{id}` aceita `id_dps` (45 caracteres) ou a chave de acesso (50 dígitos).** O front
   navega sempre pelo `id_dps`, porque é o único identificador que existe desde a criação — a
   chave só aparece depois da resposta do fisco. Usar a chave como identificador de rota quebraria
   o link de um documento em `processing`.
3. **O front só oferece os eventos do contribuinte.** `101101` (cancelamento), `101103`
   (cancelamento por substituição — só via `/substitute`), `202201`, `203202`, `204203`, `202205`,
   `203206`, `204207`, `205208`. Eventos privativos do fisco não entram em nenhum seletor.
4. **Substituição não é evento na UI.** O botão "Substituir" abre o wizard pré-preenchido e chama
   `POST /nfses/{id}/substitute`; o evento `105102` é gerado pelo fisco.
5. **ABRASF 2.04 não é suportado na v1.** Quando `provider = "abrasf204"`, o front mostra o aviso
   e desabilita DANFSE e parâmetros municipais em vez de deixar o usuário receber um 501.

- [ ] **Step 4: Escrever `calcValorLiquido` e `NFSE_STEPS`**

```tsx
type ValoresInput = {
  valor_servico: string
  desconto_incondicionado?: string
  desconto_condicionado?: string
  deducoes?: string
}

// Aritmética em centavos: parseFloat somado direto acumula erro binário e
// mostra 1000.0000000001 ao usuário.
const cents = (v?: string) => Math.round(parseFloat(v || '0') * 100) || 0

export function calcValorLiquido(v: ValoresInput): string {
  const liquido =
    cents(v.valor_servico) -
    cents(v.desconto_incondicionado) -
    cents(v.desconto_condicionado) -
    cents(v.deducoes)
  return (Math.max(liquido, 0) / 100).toFixed(2)
}

export const NFSE_STEPS = [
  {id: 'prestador', label: 'Prestador'},
  {id: 'tomador', label: 'Tomador'},
  {id: 'servico', label: 'Serviço'},
  {id: 'valores', label: 'Valores'},
  {id: 'revisao', label: 'Revisão'},
] as const satisfies readonly {id: string; label: string}[]

export type NfseStep = typeof NFSE_STEPS[number]['id']
```

## O que a F4 deliberadamente NÃO faz

- **Não implementa manifestação sobre documentos recebidos.** A tela de distribuição é somente
  leitura, porque o backend ainda não expõe a ação (F3 registrou isso).
- **Não habilita emissão por ABRASF 2.04.** A configuração pode ser salva; a emissão, o DANFSE e os
  parâmetros municipais ficam bloqueados com aviso explícito. F5.
- **Não gera DANFSE no front.** O PDF vem pronto da API, que é proxy do ADN.
- **Não replica regra fiscal no cliente.** Só as três validações condicionais da Task 2, que são
  estáveis e evitam round-trip; tudo mais é decidido pela API.
- **Não mexe nas telas de NF-e, NFC-e, CT-e e MDF-e**, com a única exceção da extração acima.
- **Não adiciona dependência.** Ícones, combobox, tabela, wizard e máscara já existem no
  repositório.
