# Webhooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar webhooks de documento fiscal no DF-e, com o motor de entrega compartilhado em `go-common` e adotado pelo billing.

**Architecture:** `go-common/webhooks` guarda as peças sem estado e um `Deliverer` genérico sobre uma interface `Store` pequena. O roteamento de eventos (fan-out) fica em cada serviço, porque depende do domínio. Billing ganha um adaptador sobre o repositório atual; o DF-e ganha tabela, repositório, serviço, API, Lambda entregadora e UI.

**Tech Stack:** Go 1.27, DynamoDB, Fiber v3, Lambda + EventBridge, CDK TypeScript, Next.js.

**Spec:** `docs/specs/2026-11-15-webhooks.md`

## Global Constraints

- Três PRs, nesta ordem: (1) `ctech-go-common` (minor novo), (2) `ctech-billing` sem mudança de comportamento nem de layout, (3) `ctech-dfe`.
- Assinatura: HMAC-SHA256 sobre `timestamp.body`, formato `v1=<hex>`. Billing mantém o prefixo de cabeçalho `X-Billing-`; DF-e usa `X-Ctech-` (`Signature`, `Timestamp`, `Event-Id`, `Event-Type`).
- `MaxFailureRun = 12`, `MaxDeliveryAttempts = 8`, `Backoff` exponencial de 30 s com teto de 12 h, timeout de 10 s por tentativa, resposta guardada até 512 bytes, TTL de 90 dias.
- Corpo do DF-e: `id`, `type`, `occurred_at`, `data{id, access_key, status, rejection{code,message}}`. Nada além disso.
- Tipos da v1: `document.authorized`, `document.rejected`, `document.failed`, `ping`.
- HTTPS obrigatório, segredo ≥ 32 caracteres mostrado uma vez, máximo 5 endpoints por organização, só owner/admin cadastram e reenviam.
- Sem NAT, sem métrica custom, sem alarme CloudWatch; alerta de desativação via `alerts` do go-common.
- Erros RFC 7807 (`problem`). Sem travessão em texto visível. `npm run lint` com zero avisos.
- Toda mudança documentada na mesma alteração (DOCS.md, CONDUCT.md se houver restrição nova, guia `/guide`).

## Review Focus

- URL que resolve para IP privado (`10.x`, `169.254.169.254`, `::1`) no cadastro e na entrega: recusa nos dois momentos, inclusive DNS que muda depois do cadastro.
- Endpoint que responde 3xx: conta como falha, não segue o redirect.
- Endpoint que responde ao desafio com corpo diferente ou com status ≠ 200: cadastro recusado, nada gravado.
- Receptor lento ou morto com muitas entregas na fila: uma falha adia o resto do mesmo endpoint e não trava os outros.
- Entrega repetida (retentativa após timeout que o receptor já processou): `X-Ctech-Event-Id` idêntico em todas as tentativas.
- Webhook quebrado ou ausente: o `ResultsConsumer` continua processando o resultado.
- Replay de entrega de endpoint desativado ou apagado: erro claro, nada é enviado.

### Task 2: `Deliverer` e `Store`

**Files:**
- Create: `ctech-go-common/webhooks/deliverer.go`, `store.go`
- Test: `ctech-go-common/webhooks/deliverer_test.go` (com `fakeStore` em memória)

**Interfaces:**
- Produces (em `store.go`):
  ```go
  type Endpoint struct{ ID, URL, Secret string; Active, Reopenable bool }
  type Event struct{ ID, Type string; Body []byte }          // Body já renderizado pelo serviço
  type Delivery struct{ EventID, EndpointID, Group string; Attempts int; NextAttemptAt string }
  type Due struct{ Delivery Delivery; Event Event }
  type Attempt struct{ Number, StatusCode int; DurationMs int64; Response, Error string }
  var ErrEndpointGone = errors.New("webhook endpoint no longer exists")
  type Store interface {
      DueDeliveries(ctx context.Context, limit int) ([]Due, error)
      GetEndpoint(ctx context.Context, d Delivery) (*Endpoint, error)   // ErrEndpointGone quando apagado
      RecordAttempt(ctx context.Context, d Delivery, a Attempt, now time.Time) error
      MarkDelivered(ctx context.Context, d Delivery, status int, now time.Time) error
      MarkAttemptFailed(ctx context.Context, d Delivery, status int, cause string, now time.Time) error
      Defer(ctx context.Context, d Delivery, until, now time.Time) error
      Close(ctx context.Context, d Delivery, cause string, now time.Time) error
      RecordHealth(ctx context.Context, e Endpoint, ok bool, detail string, now time.Time) error
      Requeue(ctx context.Context, d Delivery, now time.Time) error      // replay: volta a pendente, devido agora
  }
  ```
  `Group` é a chave de ordem serial (billing: `org|livemode|endpoint`; DF-e: `org|endpoint`).
- Produces (em `deliverer.go`):
  - `type Config struct{ HeaderPrefix, UserAgent string; Workers int; Client *http.Client }` (Client nulo = `NewGuardedClient(DeliveryTimeout)`; Workers < 1 vira 1)
  - `func NewDeliverer(store Store, cfg Config) *Deliverer`
  - `type Result struct{ Examined, Handled, Deferred, Failed int; Errors []string }`
  - `func (d *Deliverer) Deliver(ctx context.Context, limit int, now time.Time) Result` (para no primeiro não devido; agrupa por `Group`; um grupo em série, grupos em paralelo até `Workers`)
  - `func (d *Deliverer) DeliverFresh(ctx context.Context, items []Due, now time.Time) Result` (tenta sem passar pela fila; o chamador depois chama `Deliver` e pula os repetidos por `EventID+"#"+EndpointID`; mantenha esse helper em `Result` ou parâmetro `skip map[string]bool` em `DeliverSkipping`)
  - `func (d *Deliverer) Redeliver(ctx context.Context, due Due, now time.Time) error` (`Requeue` e uma tentativa imediata; endpoint apagado ou inativo e não reabrível devolve erro sem enviar)
- Lógica a mover de `ctech-billing/api/internal/services/delivering.go`: `attemptAll`, `attempt`, `post`, `isDue`, `failureDetail`, `trippedRecheck`, `disabledRecheck`.
